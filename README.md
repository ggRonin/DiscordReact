# DiscordReact

Бот, который следит за каналами Discord и ставит реакции на сообщения с нужными словами. Работает с несколькими аккаунтами, каналами и словами сразу.

> ⚠️ Бот использует токен **обычного пользовательского аккаунта** (self-bot). Это нарушает Terms of Service Discord и может привести к блокировке аккаунта. Используйте на свой риск и лучше на аккаунтах, которых не жалко потерять. Токен — это доступ к аккаунту: никому его не показывайте и не коммитьте.

## Что делает

- Держит каждый аккаунт онлайн через gateway, как настоящий веб-клиент (IDENTIFY, heartbeat, resume).
- Все запросы идут с отпечатком Chrome (TLS/HTTP2 через `curl_cffi`), с браузерными заголовками и `x-super-properties`. Номер сборки клиента берётся с сайта Discord при старте.
- Раз в 15–30 секунд читает последние 50 сообщений каждого канала и ищет самое новое, где встречается любое из слов (в тексте, заголовке, описании, полях, подписи и авторе эмбедов; регистр и markdown не важны).
- Ставит реакции (обычные или кастомные) со случайными паузами. Одно сообщение обрабатывается один раз, уже стоящие реакции не дублируются.
- Для каждого аккаунта можно указать свой прокси. Если прокси перестал работать, бот берёт следующий из `Proxy.txt`, убирает его оттуда и подставляет аккаунту вместо нерабочего.
- Запоминает, на каком сообщении остановился, отдельно по каждому каналу и аккаунту.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
```

Нужен Python 3.11+.

## Настройка

Скопируйте примеры и заполните:

| Пример | Копия | Назначение |
|--------|-------|------------|
| `config.example.json` | `config.json` | каналы, слова, реакции |
| `accounts.txt.example` | `accounts.txt` | токены аккаунтов (+ прокси) |
| `Proxy.txt.example` | `Proxy.txt` | запасные прокси (необязательно) |
| `.env.example` | `.env` | локаль и часовой пояс (необязательно) |

### config.json

```json
{
  "keywords": ["Click the emoji below to join"],
  "emoji": ["👍", "Swrd900:1387054688477642782"],
  "react_on_first_run": true,
  "channels": [
    "https://discord.com/channels/111111111111111111/222222222222222222",
    "333333333333333333",
    {
      "url": "https://discord.com/channels/444444444444444444/555555555555555555",
      "keywords": ["airdrop", "claim"],
      "emoji": ["🔥"]
    }
  ]
}
```

- **`channels`** — ссылка на канал целиком (лучше: из неё берётся сервер), просто ID канала или объект с настройками канала. ID канала получить: ПКМ по каналу → «Копировать ссылку на канал».
- **`keywords`** — список слов или фраз. Реакция ставится, если найдено **любое** из них. Общий список можно переопределить для отдельного канала.
- **`emoji`** — список реакций, ставятся все по порядку. Обычные эмодзи пишутся символом (`"👍"`). Для эмодзи с невидимым модификатором надёжнее код: `"⚔️"` (⚔️). Кастомные эмодзи пишутся как `имя:id`.
- **`react_on_first_run`** — что делать при первом запуске канала (когда ещё нет файла состояния):
  - `true` (по умолчанию): найти последнее сообщение с нужными словами и поставить реакцию, если её ещё нет;
  - `false`: считать все текущие сообщения старыми и реагировать только на новые.

  Можно задать и отдельно для канала.

**Как узнать `id` кастомного эмодзи.** Найдите сообщение, где уже стоит эта реакция, и посмотрите её в ответе API (`reactions[].emoji.id`), либо ПКМ по эмодзи → «Копировать ссылку»: число в ссылке `…/emojis/<id>.png` и есть `id`. Имя — то, что показывается при наведении (`:Swrd900:`).

### accounts.txt

Один аккаунт на строку: `токен` или `токен,прокси`. Строки, начинающиеся с `#`, игнорируются.

```
# без прокси: аккаунт работает напрямую
MTIz...token_of_account_1
# с прокси
MTIz...token_of_account_2,user:pass@host:port
```

Если файла нет, используется `DISCORD_TOKEN` из `.env` (один аккаунт).

Аккаунт должен состоять на серверах отслеживаемых каналов и видеть их.

### Proxy.txt (необязательно)

Запасные прокси, по одному на строку, формат `user:pass@host:port`:

```
user:pass@host:port
user:pass@host:port
```

Правила:
- Аккаунту **без** прокси в `accounts.txt` прокси не назначаются, он работает напрямую.
- Если у аккаунта прокси 3 раза подряд не смог подключиться, бот берёт первую строку из `Proxy.txt`, **удаляет её из файла** и записывает аккаунту в `accounts.txt` вместо нерабочей. Нерабочий прокси в пул не возвращается.
- Если запасных прокси не осталось, бот пишет об этом в лог и продолжает со старым.
- Логи показывают только `host:port`, без логина и пароля.

### .env (необязательно)

```
LOCALE=en-US
TIMEZONE=Europe/Kyiv
```

Локаль и часовой пояс, которые бот сообщает Discord. Подберите под свой аккаунт/прокси.

## Запуск

```bash
python main.py
```

Пример вывода:

```
2 account(s), 3 channel(s)
[12:02:31] [#1] gateway: online as user1
[12:02:35] [#1 user1] logged in, watching: 2222… [click the emoji below to join]; …
[12:03:02] [#1 user1] channel 2222…: react Swrd900:1387… on 1546…: 204
```

Код `204` — реакция поставлена. `403`/`404` — нет прав или сообщения нет; такое сообщение пропускается.

Аккаунты запускаются по очереди с паузой 5–20 секунд, каждый в своём потоке. Если аккаунт получает `401` или gateway отклоняет токен, останавливается только он.

## Файлы

| Файл | Описание | В git |
|------|----------|-------|
| `main.py` | сам бот | да |
| `config.example.json`, `accounts.txt.example`, `Proxy.txt.example`, `.env.example` | примеры | да |
| `config.json` | ваши каналы и слова | нет |
| `accounts.txt` | токены и прокси аккаунтов | **нет** |
| `Proxy.txt` | пул запасных прокси | **нет** |
| `.env` | локаль, часовой пояс | **нет** |
| `<id канала>.json` | состояние: последнее обработанное сообщение по каждому аккаунту | нет |

Чтобы бот заново обработал текущее последнее сообщение канала, остановите его и удалите файл `<id канала>.json`.

## Настройки в коде

В начале `main.py`:

| Константа | По умолчанию | Смысл |
|-----------|--------------|-------|
| `POLL_MIN`, `POLL_MAX` | 15, 30 | пауза между опросами, секунды |
| `CHANNEL_GAP_MIN/MAX` | 2, 5 | пауза между каналами в одном цикле |
| `REACT_DELAY_MIN/MAX` | 3, 12 | пауза перед первой реакцией |
| `ACCOUNT_START_MIN/MAX` | 5, 20 | пауза между стартами аккаунтов |
| `HISTORY_LIMIT` | 50 | сколько последних сообщений смотреть |
| `PROXY_FAIL_LIMIT` | 3 | сколько сбоев подряд до замены прокси |

Чем чаще опрос и чем больше аккаунтов на одном IP, тем выше риск блокировки.

## Ограничения

- Реагирует только на самое новое сообщение с нужными словами за один опрос.
- Смотрит только последние 50 сообщений канала: в очень активных каналах нужное сообщение может выйти за это окно.
- Ограничения по возрасту сообщения нет, включая первый запуск.
- Кастомный эмодзи с другого сервера можно поставить, только если такая реакция уже есть на сообщении (без Nitro).
